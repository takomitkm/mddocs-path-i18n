# 设计说明

每个决定都附了理由和它挡掉的具体事故。想改之前先读这一页。

## 1. 产物树，不就地改名

**决定**：`apply` 只往 `--out` 写，永远不改 vault；vault 与产物之间不存在同步关系，产物每次整棵重建。

**理由**：就地改名是不可逆的。原项目那套脚本里有一套"反向恢复"模式，靠把脚本拷到翻译后的目录里再跑一趟——两边就此各有一份真值，一次没跑回去就永久漂移，且没有任何对账手段。产物树则是：源永远只有一棵，产物随时可弃可重建，退出成本为零。

**代价**：产物里的人工修改会丢。这正好是想要的——要改就改源。

## 2. 身份用路径键，不用稳定 id

**决定**：翻译表的键是 vault 相对路径；英文侧改名/移动后，旧键变 orphan，`verify` 会列出来。

**理由**：稳定 id 需要给每页加一个 frontmatter 字段（或维护一张 id↔路径表），这对"只想翻译文件名"的场景是重税：几百篇笔记都要动，校验规则（比如"H1 必须与文件名一致"）也要跟着改。

**代价与兜底**：英文侧移动一次目录，那一段的中文名要重新挂到新键上。工具把这变成一次显式的 orphan 报告，而不是静默丢失。真要长期稳定，扩展点见 §9。

## 3. 数据文件用 TSV，不用 YAML

**决定**：`pathmap.map.tsv`，`路径 \t 名字 \t 备注`，UTF-8 无 BOM、LF。

**理由**：翻译表是**人**在改，不是程序在改。TSV 双击进 Excel/LibreOffice 就是两列，改完存回去；git diff 一行一处改动，review 得动；解析不需要任何依赖。YAML 的缩进、引号、中文冒号会在这一步反复咬人，而它的表达能力在这里一点也用不上。

**代价**：没有嵌套结构。确实不需要——段级拼接已经把层次交给了路径本身。

## 4. verify 独立重解析产物

**决定**：`verify` 不读 `apply` 的中间结果，而是把产物树重新走一遍、重新解析每个引用。

**理由**：如果校验复用生成时的索引，那它只能证明"我以为我写对了"，证明不了"产物里链接是通的"。两者的差别正好是本类工具最容易翻车的地方：索引对、落盘错；或者改名对、相对距离算错。

**判据**：产物内死链 = 0、产物内重名 = 0、无路径冲突、无空转 glob。

## 5. 歧义硬拒绝，不猜

**决定**：两篇同名页时 `[[same]]` 报告并保持原样；两个源路径落到同一产物路径时**拒绝出树**。

**理由**：Obsidian 的最短链接按**文件名**解析，同名即真歧义。任何"取第一个／取最近"的启发式都会在某一页上悄悄指向错的文档，而这种错误在阅读时完全看不出来——只会表现为"某天发现链错了"。硬拒绝把代价前移到构建时。

## 6. frontmatter 为什么不动

**决定**：`title`、`aliases`、`tags` 一律不碰。

**理由**：frontmatter 是**语义**层，不是路径层。`aliases` 的正确内容取决于宿主（Obsidian 的别名是给人搜的，静态站的 aliases 是重定向），改错了比不改更糟。真要"旧中文 URL 不 404"，那是单独一件事（发 `aliases`／重定向页），应该由消费者决定，不该由路径工具顺手代劳。

## 7. 代码先遮罩

**决定**：围栏代码块（含未闭合的）与行内代码在改写前换成占位符。

**理由**：文档里大量出现"示例中的链接"，比如教程教你写 `[[双链]]`。不遮罩就会把示例改坏，而且改坏了很难发现——示例本来就不该解析。

已知缺口：多反引号行内片段（`` ``a`b`` ``）不遮罩，因为可靠地匹配它需要真正的词法扫描；围栏块不受影响。

## 8. 为什么不走 slug / permalink 那一套

**决定**：不走。

**理由**（实测证据）：Quartz 的 `permalink` 只是别名跳转，内容页真实 URL、sitemap、RSS、搜索索引仍由**文件路径推导的 slug** 决定，文件一挪跳转目标就跟着挪（[quartz#2572](https://github.com/jackyzha0/quartz/issues/2572)）。next-intl 的 `pathnames` 那类"每语言一套路径段"是真正优雅的解法，但官方文档明确写着静态导出用不了——"You can't use pathnames, as these require server-side rewrites"。

结论：**静态站上想让 URL／侧边栏是中文，路径就必须真的是中文**。这也是本工具存在的唯一理由。

## 9. 扩展点（想清楚再动）

| 方向 | 值不值得 | 说明 |
|---|---|---|
| 稳定 id（frontmatter `id:` 或旁挂 id 表） | 值得，但侵入源 | 让翻译名在英文改名后仍跟着走；orphan 报告退化成不需要 |
| 生成 `aliases`／重定向页 | 值得，作为可选输出 | 旧中文 URL 不断链；需要消费者的 URL 规则，属于集成层 |
| 多语言并行（一张表管 `zh`＋`ja`） | 简单 | 把 `map` 变成 `maps/<locale>.tsv`，其余不变 |
| Obsidian 侧消费者（就地改名） | 慎 | 调 `app.fileManager.renameFile()`；语义由 Obsidian 负责，本工具的 map 复用。但它会真的改工作树，`git`／`rg` 在中文路径上的历史坑要自己评估 |
| 正文/标题翻译 | 不是这个工具 | 属于翻译流水线，与路径无关 |

## 10. 安全阀的由来

| 阀 | 挡掉的真实事故 |
|---|---|
| 产物不能在 vault 内 | 一次 `--out .` 就把源树改了，且没有备份 |
| 无标记不覆盖 | 指向一个已有目录（比如 `dist/`）导致别人的构建产物被 `rmtree` |
| 冲突即拒 | 两个目录翻成同名，产物里后者覆盖前者，页面静默消失 |
| `unresolved` 只报告不改 | 把钉在"还没写"的页上的链接改成别的页，等于篡改意图 |
